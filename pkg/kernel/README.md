# pkg/kernel — 단계를 가로지르는 공유 커널

`pkg/{discovery, inventory, provisioning}`이 **단계별 로직**이라면, `kernel`은 **어느 단계에도 속하지 않지만 여럿이 함께 쓰는 것**을 담는다.

## 무엇이 여기 들어오나 — 판정 기준

한 조각을 kernel에 둘지 말지는 세 질문으로 갈린다:

1. **둘 이상의 단계가 쓰는가?** — 한 단계만 쓰면 그 단계 패키지에 둔다.
2. **단계에 역의존하지 않는가?** — kernel은 `pkg/discovery`·`pkg/inventory`·`pkg/provisioning`을 **import하지 않는다.** 이 방향을 지켜야 순환이 안 생기고, 단계를 떼어내도 kernel이 따라오지 않는다.
3. **결정론적인가?** — 여기 있는 것 대부분은 **파생 규칙**(같은 입력 → 항상 같은 출력)이다. 규칙이 한 곳에 있어야 원본에서 **재계산으로 재현**된다(§0.2).

세 번째가 핵심이다. 성숙도 판정·등급 분류·지문 파생 같은 규칙이 collector나 단계에 흩어지면, 규칙이 바뀌었을 때 **과거 데이터를 다시 계산할 수 없다.** 그래서 collector는 *관측*만 하고, 판정 규칙은 전부 이쪽으로 모은다.

## 구성

| 패키지 | 하는 일 | 왜 공유인가 |
|---|---|---|
| [`scope`](scope) | **관리 대상 경계의 게이트**(§0.4). 노드 등재 게이트(`Master`)와 **자산 스코프**(`AssetPolicy`) | 디스커버리가 수집 대상을 거르고, 인벤토리가 적재 대상을 거른다.<br>설계: [인벤토리 §14](../../inventory/인벤토리_설계.md) |
| [`posture`](posture) | 협상 KEX 그룹 문자열 → **양자내성 등급**(🟢 PQC/하이브리드 · 🔴 고전 · ⚪ 불명) + 성숙도(표준 vs 실험) | 디스커버리 뷰·인벤토리 토폴로지·프로비저닝 분기가 같은 판정을 써야 한다.<br>collector는 그룹 *이름*만 관측하고 분류는 여기서(§0.2) |
| [`registry`](registry) | 결정론적 **시그니처·참조 데이터** — OpenSSL fork 판별, PQC 알고리즘 성숙도, JCA provider 능력, remediation 권고 | 강화 단계의 입력이자 프로비저닝 분기의 근거.<br>참조 데이터라 코드가 아니라 **데이터로** 갱신된다(§2.3) |
| [`sign`](sign) | 수집 결과 **ed25519 서명·검증**(§2.7) — 서명 대상 바이트의 정규화 포함 | collector(엣지)가 서명하고 코어(중앙)가 검증한다 — 양쪽이 **같은 정규화**를 써야만 성립 |
| [`machineid`](machineid) | 머신 **상관 지문** 수집과 결정론적 self-id 부여(§0.4) | 같은 머신이면 항상 같은 값이라 중복 등록이 드러난다.<br>*IP는 ID가 아니라 로케이터*라는 원칙의 구현 |

## 지켜지는 규칙 몇 가지

- **정직한 빈 값** — `machineid`는 못 읽은 지문을 추측하지 않고 빈 값으로 남긴다. `posture`는 모르는 그룹을 고전으로 넘겨짚지 않고 ⚪ 불명으로 둔다(§2.6).
- **서명 정규화는 계약이다** — `sign.Canonical`이 덮는 범위(노드 앵커·원시 포맷·CBOM 본문·관측 엣지)가 바뀌면 **기존 서명이 전부 무효**가 된다. 필드를 더할 땐 이 함수를 함께 봐야 한다.
- **참조 데이터의 갱신 주기** — `registry`의 성숙도·시그니처는 표준·라이브러리가 움직이면 따라 바뀐다. 코드 로직이 아니라 **데이터**로 두는 이유이며, 바뀌면 과거 스냅샷을 재계산해 새 판정을 얻는다(§0.2).

## 어디서 쓰이나

```
collector(관측) ──▶ scope.Master(게이트) ──▶ normalize(강화) ──▶ history
                                              └ registry(성숙도·provider·fork)
                                              └ posture(등급)
                     sign(서명)  ──────────────▶ sign(검증)
                     scope.AssetPolicy(자산 게이트) ──▶ 적재
```
