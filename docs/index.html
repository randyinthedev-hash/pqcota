How it works작동 방식

① Discovery① 관측 Small collector programs observe what a system actually uses: loaded libraries, a live JVM's provider chain, the algorithms negotiated in handshakes. 작은 수집 프로그램으로 시스템이 실제로 쓰는 것을 관측합니다: 로드된 라이브러리, 실행 중인 JVM의 provider 체인, 핸드셰이크에서 협상된 알고리즘.
② Inventory② 인벤토리 Ties each observation to its node and application and keeps the history. When the state changes it leaves a new snapshot, so you can compare it with the earlier one. 관측 결과를 노드와 앱에 연결하고 이력을 보존합니다. 상태가 바뀌면 새 스냅샷을 남겨 이전 상태와 비교합니다.
③ Provisioning③ 전환물 생성 People write and approve a plan. From it the tool generates configuration fragments and Ansible playbooks: apply and rollback come out together. Running them is your Ansible's job. 사람이 계획을 쓰고 승인합니다. 도구는 그 계획에서 설정 조각과 Ansible 플레이북을 생성하며, 적용용과 되돌림용이 함께 나옵니다. 생성된 플레이북은 사용자가 자신의 Ansible로 실행합니다.

Scope and limits지원 범위와 한계

  • Linux: observation and change generation for OpenSSL and Java. Windows (CNG): observation only, for now. Linux: OpenSSL과 Java의 관측과 변경 생성. Windows(CNG): 지금은 관측만 합니다.
  • It does not decide what to migrate, score or judge, apply changes for you, scan source code, or certify compliance. 하지 않는 일: 무엇을 이관할지 정하기, 점수를 매기거나 판정하기, 대신 적용하기, 소스 코드 스캔, 규정 준수 인증.
  • Not observed is not the same as not there. A layer that could not be collected is recorded as a gap, with the strength of the evidence beside it. 관측하지 못한 것은 「없음」이 아닙니다. 수집하지 못한 계층은 증거의 강도와 함께 갭으로 남깁니다.
  • pre-1.0 software, shown on test systems. The FAQ covers data, privileges and operations. 1.0 이전 소프트웨어이며 시험 시스템에서 시연했습니다. 데이터 취급, 필요한 권한, 운영 방법은 FAQ를 참고하세요.
