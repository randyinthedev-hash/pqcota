# network-collector: 협상된 알고리즘을 수동 관측

**설계 목표**: 설정 파일이 무엇을 *허용*하는지가 아니라 **회선에서 실제로 무엇이 협상됐는지**를 본다. `ssl_ciphers` 목록에 PQC가 있어도 상대가 지원하지 않으면 고전으로 떨어진다. 그 진실은 핸드셰이크에만 있다.

> **§ 표기**: 별도 언급이 없으면 [규정서](../../../docs/regulation.md)의 절 번호다.

근거: [디스커버리 설계 §2.3](../../design.md) · 인수 기준: [테스트케이스 TD-NETWORK-1–13](../../testcases.md)

## 무엇을 보고, 무엇을 안 보나

- **본다**: TLS/SSH **평문 핸드셰이크**의 협상 KEX 그룹·cipher, 연결 종단(누가 누구와).
- **안 본다**: **복호화하지 않는다.** 페이로드는 건드리지 않고 핸드셰이크만 읽는다. 수동 관측이라 대상 시스템에 아무것도 주입하지 않는다.

## 산출은 노드 자산이 아니라 **통신 엣지**다

다른 두 collector는 노드 *내부* 자산(`Finding`)을 낸다. 이쪽은 **노드 사이**의 관계: `ObservedEdge`: 를 낸다. TLS를 쓴다고 그 노드에 OpenSSL이 있다고 붙이지 않는다(TLS ≠ OpenSSL). 이 엣지들이 인벤토리 [§6 통신 토폴로지](../../../inventory/design.md)의 입력이 된다.

## 경계: 등급은 코어가 판정한다

collector는 협상 그룹을 **이름으로 관측**하는 데서 멈춘다. 🟢/🔴/⚪ 등급 분류는 코어 파생(`pkg/kernel/posture`)이다(§1.2: 규칙이 한 곳에 있어야 재계산으로 재현된다).

미등록 코드포인트는 **`unknown(0xNNNN)`으로 정직히** 표기한다. 임의로 추정해 이름을 붙이지 않는다.

## 중복과 방향: 한쪽에서만 방출한다

같은 핸드셰이크는 양 끝에서 잡힌다. 그대로 두면 엣지가 두 번 생기고 방향도 뒤집힌다. 그래서 **로컬이 클라이언트일 때만 방출**한다(서버 = 낮은 포트 쪽). 서버측에서 본 것은 상대 노드가 보고한다. IP→노드 잇기는 코어의 스코프 마스터가 한다(§1.4).

**자기참조**(자기 노드를 향한 자기 트래픽)는 엣지에서 제외한다(TD-NETWORK-8).

## 정직성: 관측하지 못한 것을 "없다"로 만들지 않는다

- **캡처 자체가 불가**하면(예: `CAP_NET_RAW` 없음) RPC 실패로 터뜨리지 않고 `ErrCaptureUnavailable`로 감싸 **완전성 갭으로 강등**한다(TD-NETWORK-13). 권한 문제가 "통신이 없다"로 둔갑하지 않는다.
- **관측 구간 동안 흐른 것만** 본다. 유휴 링크·야간 배치·DR 경로는 안 잡힌다. 이건 부재가 아니라 **갭**이며, 완전성 맵에 그렇게 적힌다(§2.6).
- 조각화·VLAN 다중 태그·절단된 프레임은 **정직히 스킵**한다(추측 파싱 금지).

## 순수 부분과 부수 부분을 갈랐다

프레임 해체(`DissectTCPPayload`)와 핸드셰이크 파싱(`ParseHandshakePayload`)은 **순수 함수**다. 소켓을 여는 `LiveSource`만 부수효과를 갖는다. 덕분에 파싱 로직 전체가 **캡처 권한·libpcap 없이 TDD**되고, 라이브 캡처는 얇은 조립층으로 남는다.

## 전제

- **Linux 전용**: AF_PACKET 원시 소켓(`//go:build linux`).
- **`CAP_NET_RAW`** 필요(없으면 위 갭 경로).
- libpcap 비의존: 순수 Go.

## 구조

| 파일 | 역할 |
|---|---|
| `capture_linux.go` | AF_PACKET 라이브 캡처(유일한 부수효과 층) |
| `dissect.go` · `cursor.go` | Ethernet/IPv4/IPv6/TCP 해체 (순수) |
| `tls.go` · `ssh.go` · `handshake.go` | TLS 레코드·SSH 배너/KEXINIT 파싱 (순수) |
| `groups.go` | KEX 코드포인트 → 이름(IANA + PQC 하이브리드) |
| `edge.go` | 관측 → `ObservedEdge` 조립, 방향·자기참조 처리 |
| `service.go` | intake 계약(§1.6) 노출, 능력 신고 |
