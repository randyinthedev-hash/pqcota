STEP 01

Observe: see what is running관측: 실행 중인 것을 본다

A provider missing from the config file is in the running JVM's chain.
Same node, two sources: the config file, and what the collector found by attaching to the JVM.설정 파일에는 없는 provider가 실행 중인 JVM 체인에는 있다.
같은 노드를 두 근거로 본다: 설정 파일, 그리고 JVM에 attach해 수집한 결과.
java.security vs attach → getProviders()
STEP 02

Generate: from a plan to deliverables전환물 생성: 계획에서 배포물로

A person prepares two things: the plan JSON and the provider module file.
The tool writes the config fragments and the apply and rollback playbooks,
then we count what OpenSSL lists, to see whether the change took effect.사람이 준비하는 것은 둘이다: 계획 JSON과 provider 모듈 파일.
도구가 설정 조각과 적용용·되돌림용 플레이북을 만들고,
OpenSSL이 나열하는 항목을 세어 실제로 반영됐는지 본다.
plan.json + oqsprovider.so → pqcota-provision → provision.yml → ML-KEM 0 → 14 → 0
STEP 03

Honesty: what was not observed정직성: 관측하지 못한 것

A layer not observed for lack of permission is never recorded as "none".
Mixed in, it would be misread as "this node has none".권한이 없어 관측하지 못한 계층을 「없음」으로 적지 않는다.
섞어 적으면 「이 노드에는 없다」로 잘못 읽히기 때문이다.
